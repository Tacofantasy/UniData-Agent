# Agent 记忆策略：存最终答案 + 工具调用摘要

ReAct 循环中产生的 Thought/Action/Observation 中间步骤不直接存入对话记忆。只存两类消息：
1. 最终 assistant 回答（与现有机制一致）
2. 工具调用摘要（结构化记录调了什么工具、查到了什么关键信息）

理由：
1. 纯丢弃中间步骤在 Agent 场景下体验差——用户常追问"你刚才查到的那个数据"，丢失工具结果会让 Agent 显得健忘
2. 全量存储的数据库和 Token 成本不值得——ReAct 一轮可能产生 3-5 条中间消息
3. 摘要方案是工程甜点——Token 开销小但关键上下文不丢

实现：复用 t_message 表，新增 message_type 字段区分"正常对话"和"工具调用摘要"。
